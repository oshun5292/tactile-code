# 段階2の契約: ボード操作(ドラッグ・ズーム/パン・手書き・消しゴム)

> **2026-10-21 の改訂(ユーザー決定)**: 実機で試した結果、**コネクタ(カードを線でつなぐ機能)は作らない**ことにした。以下の「Edge」「`add_edge`」「`remove_edge`」「ハンドル」「つなぐ」に関する記述は**撤去済み(履歴として残している)**。`get_board` の戻り値は `{ strokes, viewport }`。保存ファイルに古い `edges` が残っていても、読めて、次の保存で消える。
> あわせて、手書きに **消しゴム(線ごと消す)** と **円の自動整形(ほぼ閉じた丸を、手書き風に重なる楕円へ)** を追加した。どちらも、フロントエンドだけで実現する(消しゴムは既存の `remove_stroke`、「戻す」での復元は既存の `add_stroke`)。「戻す」は操作の履歴(描いた・消した・全消し)を新しい順に取り消す。履歴は画面の状態で、再起動で消える。

段階1の契約(`docs/stage1-contract.md`)の続き。**コードが正**。実装と食い違ったら、この文書を直す。
要件: `docs/requirements.html` の FR-05, FR-06。見た目の見本: `samples/36-gentle-bento.html`(手書きの丸囲み・下線・コネクタ線、ペンのツールバー)。

## 1. ゴール(段階2)
- カードを**ドラッグで動かせ**、位置が保存される(再起動後も同じ位置)。
- カード同士を**線でつなげる**(手書き風の細い線、両端に小さな丸)。線の選択と削除ができる。
- **ズーム・パン**(ホイールで拡大縮小、背景をドラッグで移動)。表示位置も保存する。
- **手書きペン**: ペンをONにして、ボード上に自由に描ける。色の選択(4色)、1つ戻す、全消し。描いたものは保存され、再起動後も残る。丸囲み・下線は「ペンで描いたもの」として扱う(専用の図形ツールは作らない)。
- エディタ・メモ編集の仕様は変えない(段階1のまま)。

## 2. 型(JSON は camelCase)

```ts
type Edge = { id: string; source: string; target: string };           // source / target は ProjectSummary.id
type Stroke = { id: string; color: string; width: number; points: [number, number][] };
//   color: "#rrggbb"。width: ボード座標での太さ(1〜12)。points: ボード(フロー)座標。2点以上。
type Viewport = { x: number; y: number; zoom: number };              // zoom: 0.2〜2
type BoardState = { edges: Edge[]; strokes: Stroke[]; viewport: Viewport | null };
```
- 座標は、React Flow の「フロー座標」(ズーム・パンの影響を受けない、ボード上の絶対位置)。`ProjectSummary.position`(段階1)も、同じ座標系の**カード左上**として扱う。
  (段階1では、ボード左上の余白 (72,150) からの相対 px として配置していた。段階2からは、フロー座標をそのまま使い、初期の見え方(初期ビューポート)でその余白を作る。)

## 3. コマンド(`invoke`)。引数名も camelCase。エラーは日本語の短い文字列

| コマンド | 引数 | 戻り値 | 意味 |
|---|---|---|---|
| `get_board` | なし | `BoardState` | つなぎ・手書き・表示位置をまとめて返す |
| `add_edge` | `{ source: string, target: string }` | `Edge` | つなぐ。同じ2枚の重複(向き違いも)は「すでにつながっています」、自分自身は「同じカードにはつなげません」、存在しない id はエラー |
| `remove_edge` | `{ id: string }` | `null` | つなぎを外す |
| `add_stroke` | `{ color: string, width: number, points: [number, number][] }` | `Stroke` | 手書きの1本を追加。色が `#rrggbb` でない/太さが範囲外/点が2未満または5,000超はエラー。全体で2,000本まで |
| `remove_stroke` | `{ id: string }` | `null` | 1本消す(「戻す」で使う) |
| `clear_strokes` | なし | `null` | 手書きを全部消す |
| `save_viewport` | `{ x: number, y: number, zoom: number }` | `null` | 表示位置の保存(連続で呼ばれるので、軽く) |

- 既存の `move_project`(段階1)を、ドラッグ終了時に呼ぶ。
- `remove_project` は、そのカードにつながっている `edges` も**一緒に消す**(手書きは消さない)。
- `list_projects` / `get_board` は、画面起動時に呼ぶ。

## 4. 保存ファイル(`projects.json`)を v2 に
```json
{ "schemaVersion": 2,
  "projects": [ ... 段階1のまま ... ],
  "edges": [ { "id": "...", "source": "...", "target": "..." } ],
  "strokes": [ { "id": "...", "color": "#34302b", "width": 3, "points": [[0,0],[10,4]] } ],
  "viewport": { "x": 0, "y": 0, "zoom": 1 } }
```
- v1 のファイル(`edges` `strokes` `viewport` が無い)も**そのまま読める**こと。読んだあと、次の保存で v2 として書く。テストで確認する。
- 書き込みは、段階1と同じ(一時ファイル → 置き換え)。`save_viewport` と `add_stroke` が頻繁でも壊れないよう、ストアの更新は排他制御(Mutex)のもとで行う(段階1の仕組みを使う)。

## 5. 画面(フロントエンド)の約束
- **React Flow(`@xyflow/react` 12.12、導入済み)**を使う。アトリビューション(ロゴ表示)は**消さない**(MIT。消すのは Pro 購読者向けのため)。
- カード = カスタムノード(`ProjectNode`)。中身は段階1の `ProjectCard` をそのまま使う。**編集欄(メモ・説明)や × ボタンは、ドラッグや選択の邪魔にならない**ようにする(`nodrag` クラスなど)。
- つなぐ: カードの4辺(上・右・下・左)に、ホバー時に出る小さな丸(ハンドル)。どのハンドル同士でもつなげる(`ConnectionMode.Loose`)。
- 線(エッジ)は**手書き風**: 細い(1.8〜2.4px)、ごくわずかに揺らす(座標ベースの固定の揺らぎ。毎回描画で変わらない)、両端に小さな丸。色は、つなぎ元のカードのメイン言語色の濃いトーン(36の見本のコネクタ)。選択すると太く/色が変わり、Delete / Backspace で外せる。
- ズーム 0.2〜2。ホイールで拡大縮小、背景ドラッグでパン。左下に小さなズーム操作(36の見本のペンツールバーと調和する見た目。React Flow 標準の `Controls` を CSS で整える)。表示位置は、止まってから 500ms 後に `save_viewport`(連続呼び出しを避ける)。初期表示(保存が無いとき): カードが見える位置で、左上に余白。
- **手書きペン**:
  - 左下のツールバー(36の見本: 「ペン」ボタン、色の丸4つ、「戻す」「消す」)。色は 茶墨 `#34302b` / 桃 `#e2708a` / 水色 `#5a9fe0` / 若葉 `#5fb36f`。太さは 3(ボード座標)固定でよい。
  - ペンON中: 背景ドラッグでのパンと、カードのドラッグ・選択は**無効**にして、ボード全面でポインタ(マウス・ペン・タッチ)を受け付ける。カーソルは十字。OFFで通常操作に戻る。Esc でもOFF。
  - 描画: ポインタの移動を集めて、画面座標 → フロー座標(`screenToFlowPosition`)に変換し、間引き(近すぎる点は捨てる)、なめらかな曲線(Catmull-Rom → ベジェ。`samples/assets/common.js` の `smooth` を参考に、TypeScriptで書き直す)で描く。描いた線は、ズーム・パンに追従する(フロー座標の SVG を `ViewportPortal` に描く)。
  - 離したら `add_stroke`。「戻す」= 最後の1本(`remove_stroke`)、「消す」= 確認(「手書きをすべて消しますか?」)のあと `clear_strokes`。
  - 手書きは、カードより**前面**に描く(丸囲みがカードの上に見えるように)。ペンOFFのときは、手書きはクリックを邪魔しない(`pointer-events: none`)。
- 状態管理は Zustand(段階1のストアを拡張)。Tauri呼び出しは `src/api/` のラッパーだけ。**ブラウザ(Tauri外)でも動く**よう、モックを拡張する(つなぎ・手書き・表示位置をメモリ上で。モックの初期データには、見た目確認のため、サンプルの `edges` 3本と `strokes`(丸囲み・下線・矢印風)を入れる)。

## 6. テスト
- Rust: `add_edge` の検証(重複・向き違い・自分自身・存在しない id)、`remove_project` が `edges` を巻き込んで消すこと、`add_stroke` の検証(色・太さ・点の数・本数上限)、`remove_stroke`、`clear_strokes`、`save_viewport` の往復、**v1 のファイルを読める**こと、そして `tauri::test` の IPC で、JSON の形(camelCase)が契約どおりか。
- フロント: 純粋関数(間引き、曲線パスの生成、座標変換の補助、手書き風の揺らぎ)を Vitest で。画面は、ブラウザ(モック)のスクリーンショットで確認する。
