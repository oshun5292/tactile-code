# N4 契約書(ツリーのドラッグ移動・複製)

VSCode と同じ体験: ツリーでファイル・フォルダをドラッグして別のフォルダへ移動、右クリックの「複製」。コードが正。新しい依存は追加しない。

## API(`src/api/types.ts` / `tauri.ts` は作成済み。変えない)
- 移動は既存の `renameEntry(projectId, from, to)` を使う(新しいコマンドなし)。
- `duplicateEntry(projectId, relPath) -> FsEntry`: 同じフォルダに複製。名前は `foo.ts` → `foo copy.ts` → `foo copy 2.ts` …(最初に空いているもの。拡張子の前に ` copy` / ` copy N` を入れる。拡張子なし・ドットで始まる名前(`.env` → `.env copy`)・フォルダも同様)。フォルダは中身ごと再帰コピー。

## バックエンド(src-tauri/ のみ)
- `duplicate_entry` コマンド(`commands/mod.rs` は薄く、処理は `services/fs.rs`)、`lib.rs` に登録。
- パス検証は既存の `resolve` / `locate`。ルート自体・`.git` は拒否。**リンク(リパースポイント)は、リンク自体をコピーせず、中へ入らない**(フォルダ複製の途中で出会ったリンクは飛ばす)。複製先の名前は、既存を上書きしない(`create_new` 相当)。
- フォルダ複製は、合計 5,000 ファイル・合計 200MB を超えたらエラー(途中までできたコピーは、作った分を元に戻す=ごみ箱ではなく、**作成した複製だけ**を削除。元のフォルダは絶対に触らない)。コピー元が複製先の内側になる再帰(フォルダを自分の中へ)は起きない(同じ親に作るため)。
- 日本語名・空白入り・`.git` を含まない中身のみ(`.git` というフォルダがフォルダの中にあってもコピーしない)。
- テスト: ファイル/フォルダ/拡張子なし/ドット始まり/連番、リンクの非追従、上限、元のファイルが変わらない、拒否(ルート・`.git`・不正パス)、IPC 契約。
- 完了条件: `cargo test` / `cargo clippy --all-targets -- -D warnings` / `cargo fmt --check`。

## フロントエンド(src/ のみ。api/types.ts と tauri.ts は変更しない)
- `mock.ts` に `duplicateEntry`(同じ仕様の名前付け。空フォルダ・中身ごと)。
- `FileTree.tsx`: HTML5 ドラッグ&ドロップ。ファイル・フォルダ行を `draggable` に。
  - フォルダ行(と、ツリーの空白=プロジェクトのルート)にドロップで移動。ドラッグ中は、ドロップできるフォルダを強調。自分自身・自分の子孫・今の親フォルダへのドロップは無効(強調しない)。閉じたフォルダの上に 700ms 留まったら自動で開く。
  - 移動先に同名があれば、上書きせず、トーストで「同じ名前のものがあります」。
  - 移動後は、`editorStore` の既存の名前変更の付け替え(タブ・展開・キャッシュ)を使う。未保存の編集を保つ。
  - 入力欄での名前変更中や、読み込み中の行はドラッグ不可。
- 右クリックメニューに「複製」(ファイル・フォルダ)。複製後は、そのエントリを選択して名前変更の入力に入る(VSCode と同じ)。ファイルの場合は開かなくてよい。
- 純粋関数(移動先パスの計算、無効なドロップの判定、複製名の計算=モック用)+Vitest。
- 見た目は CSS 変数に合わせ、プロジェクト色の継承を壊さない。緑の囲み(`confirm-safe`)は使わない。完了条件: `pnpm build` と `pnpm test`。可能ならブラウザ(モック)で確認し、dev サーバーは止める(ポート 1420 を空ける)。
