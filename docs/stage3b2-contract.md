# 段階3b-2 契約書(ファイル操作・VSCodeで開く)

方針(ユーザー決定): 基本は VSCode でできることと同じ。キーボードだけでの画面移動は後回し。削除は、ごみ箱へ移す(完全には消さない)。
コードが正。この文書と食い違ったらこちらを直す。依存 `trash` は追加済み(Cargo.toml)。

## 1. 範囲
- ファイル・フォルダの新規作成、名前変更(移動を含む)、削除(ごみ箱へ)。
- 「VSCodeで開く」(プロジェクト全体/選択したファイル)。
- ツリーの右クリックメニュー、F2(名前変更)、Delete(削除)、ツリー上部の「新規ファイル」「新規フォルダ」ボタン。
- 「パスをコピー」(相対パス/絶対パス)。絶対パスはプロジェクトの `path`(フロントが持つ)と連結する。
- 範囲外: ドラッグでの移動、複製、コピー&ペースト(あとで)。

## 2. API(`src/api/types.ts` と `src/api/tauri.ts` は作成済み。変えない)
- `createFile(projectId, relPath) -> FsEntry`: 空ファイル。既存なら `既存:` で始まるエラー。親フォルダが無ければエラー(親は作らない)。
- `createDir(projectId, relPath) -> FsEntry`: 既存なら `既存:`。親が無ければエラー。
- `renameEntry(projectId, fromRelPath, toRelPath) -> FsEntry`: 同じプロジェクトの内側だけ。`to` が既にあれば `既存:`(上書きしない。大文字小文字だけの違いは許す)。ルート自体・`.git`・フォルダを自分の中へ移す操作は拒否。
- `deleteEntry(projectId, relPath)`: `trash` クレートでごみ箱へ。ルート自体・`.git` は拒否。リンク(リパースポイント)は、リンク自体だけを対象にし、中身へ入らない。
- `openInVscode(projectId, relPath)`: relPath が空ならプロジェクトのフォルダ、それ以外はそのファイル/フォルダを `code` で開く。`code` が見つからなければ `VSCode:` で始まるエラー(例: 「VSCode(code コマンド)が見つかりません」)。

## 3. バックエンド(Rust。担当は src-tauri/ のみ)
- すべて既存の `resolve()` / `validate_rel` を通す。**作成・移動先は、まだ存在しないので、親フォルダを resolve して、その内側であることと名前の字句チェックを行う**(既存の `write_file` の考え方に合わせる)。
- `commands/mod.rs` に5コマンド、`lib.rs` に登録。処理は `services/fs.rs`(長くなるなら `services/fsops.rs` に分けてよい)。
- VSCode: Windows では `cmd /C code` 経由で起動(`code` は .cmd のため)。ウィンドウを出さない(`CREATE_NO_WINDOW`)。引数は、パスに空白や日本語が入っても壊れない渡し方にし、`--` の後ろに置く。起動の成否は「プロセスを起動できたか」で判定(待たない)。
- テスト: 作成(既存/親なし/不正名/予約名)、名前変更(既存/ルート/`.git`/自分の中へ/大文字小文字のみ変更)、削除(ごみ箱は実環境に依存するため、テストでは削除の対象検証=拒否系を中心に。削除の成功は一時フォルダで1件確認してよい)、IPC 契約テストに5コマンド。
- 完了条件: `cargo test` / `cargo clippy -- -D warnings` / `cargo fmt --check` が通る。

## 4. フロントエンド(担当は src/ のみ。api/types.ts と api/tauri.ts は変更しない)
- `src/api/mock.ts` に5メソッドを実装(モックのファイル群 `mockFiles.ts` をメモリ上で更新)。
- ツリー(`FileTree.tsx`): 右クリックメニュー(新規ファイル/新規フォルダ/名前を変更/削除/パスをコピー/VSCodeで開く)、行内の名前入力(Enter 確定・Esc 取消。VSCode と同じ操作感)、F2 と Delete キー、ツリー上部のボタン2つ。新規は、選択中のフォルダ(ファイルを選択中ならその親)の中に作る。作成後はそのファイルを開く。
