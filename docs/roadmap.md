**夜間にやらない作業(ユーザーの判断・承認が要る)**
- UTF-8 以外の文字コード(3b-3): `encoding_rs` 等の依存追加が必要。承認後に実施。
- Phase 2 以降の実装(認証・トークンの扱いは、提案書にユーザーが決定してから)。
- 依存の追加(`pnpm add`、`cargo add`)、main への push、PR のマージ、強制 push、履歴の書き換え。

## 4. 進め方(1項目あたり)
1. `main`(または依存する未マージブランチ)から `feat/…` を切る。依存するときは、PR の base をそのブランチにして、説明に「#◯ の上に積んでいる」と書く。
2. 契約書 `docs/stageX-contract.md` を書く(API の型・Rust の要件・フロントの要件・完了条件・触るファイルの分担)。`src/api/types.ts` と `tauri.ts` は、親が先に書く(担当同士の衝突を避ける)。
3. サブエージェント(Sonnet、**同時実行は5本まで**、1エージェント=1テーマ)に、バックエンド(src-tauri/ のみ)とフロント(src/ のみ)を分けて任せる。
4. 親が自分で検証する: `pnpm build` / `pnpm test` / `cargo test` / `cargo clippy -- -D warnings` / `cargo fmt --check`、秘密情報の検索、`git status`。
5. 小さく分けてコミット(日本語・末尾に共同作成者行)、`git push -u origin <ブランチ>`、`gh pr create`。説明に「確認したこと/未確認/既知の課題」。
6. dev サーバー(ポート 1420)とアプリのプロセスを止める。

## 5. 止まる条件(無人のとき)
- 検証(上の4)が通らず、2回直しても解消しない → 停止して、症状と試したことを報告。
- 要件に無い判断が出た → **勝手に決めず**、その項目を飛ばして次へ(飛ばした理由を記録)。
- 安全フック(`.claude/hooks/guard-delete.mjs`)にブロックされた → 回避しない。別の安全な書き方にするか、飛ばす。
- 許可リストに無い操作で確認が出て、応答が無い → 同様に飛ばす。
- 1晩のPRは、最大 6 本まで。

## 6. 朝の確認(ユーザー向け)
- 作業の記録は、各 PR の説明と、チャットの最後の報告。
- 実機で確認するもの(未確認の一覧)は、各 PR の「未確認」に集める。
- マージは、古い順(依存順)に行う。
